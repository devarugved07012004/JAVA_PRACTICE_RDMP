# JVM, JDK, JRE and Bytecode Explained

## Big Picture

```text
Java Source Code (.java)
          ↓
      JDK Compiler
          ↓
      Bytecode (.class)
          ↓
          JVM
          ↓
Machine Code
          ↓
Operating System
```

Example:

```java
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello World");
    }
}
```

You write this code in `Hello.java`.

---

# 1. JDK (Java Development Kit)

The **JDK** is a package used for **developing Java applications**.

Think of it as a **toolbox for programmers**.

It contains:

- JRE
- Java Compiler (`javac`)
- Debugging tools
- Documentation tools
- Packaging tools (`jar`)

### Example

Compile Java code:

```bash
javac Hello.java
```

This creates:

```text
Hello.class
```

### Who uses JDK?

Developers who:

- Write Java code
- Compile code
- Debug applications

### Simple Analogy

Imagine you're making a car.

- JDK = Complete factory
- Has all tools required to build the car

---

# 2. JRE (Java Runtime Environment)

The **JRE** is used to **run Java applications**.

It contains:

- JVM
- Java libraries
- Runtime files

But it **does not contain a compiler**.

So:

✅ Run Java program

```bash
java Hello
```

❌ Compile Java program

```bash
javac Hello.java
```

won't work because compiler isn't included.

### Analogy

JRE is like:

- Driver
- Fuel
- Engine support

You can drive the car but can't manufacture it.

---

# 3. JVM (Java Virtual Machine)

The **JVM** is the actual engine that executes Java programs.

It reads Java bytecode and converts it into machine code.

### Why JVM exists?

Different operating systems understand different machine code.

Examples:

- Windows
- Linux
- macOS

Instead of compiling separately for each OS, Java compiles to a common format called **bytecode**.

Then JVM runs that bytecode on any platform.

That's why Java says:

> Write Once, Run Anywhere

### Example

The same:

```text
Hello.class
```

can run on:

- Windows JVM
- Linux JVM
- macOS JVM

without changing the code.

---

# What is Bytecode?

This is the most important concept.

### Source Code

```java
System.out.println("Hello");
```

Human-readable.

Saved as:

```text
Hello.java
```

### After Compilation

Compiler converts it into:

```text
Hello.class
```

This file contains **Bytecode**.

Bytecode is:

- Not machine code
- Not source code
- Intermediate code

Example (roughly):

```text
getstatic
ldc
invokevirtual
return
```

These instructions are understood by JVM.

---

## Why Not Directly Generate Machine Code?

Suppose Java generated machine code directly.

You would need:

```text
Windows Version
Linux Version
macOS Version
```

just like C or C++.

Instead:

```text
Java Code
      ↓
Bytecode
      ↓
Any JVM
```

This makes Java portable.

---

# Relationship Between JVM, JRE and JDK

```text
JDK
 └── JRE
      └── JVM
```

So:

### JVM

Runs bytecode.

### JRE

Provides environment to run Java.

### JDK

Provides tools to create Java applications.

Suppose you install:

```text
JDK 21
```

Inside it:

```text
JDK
 ├─ javac
 ├─ javadoc
 ├─ jar
 └─ JRE
      └─ JVM
```

Then:

### Compile

```bash
javac Hello.java
```

Creates:

```text
Hello.class
```

### Run

```bash

```

JVM executes bytecode.

Output:

```text
Hello World
```

# What Happens Internally?

When you run:

```bash
java Hello
```

### Step 1

JVM loads:

```text
Hello.class
```

using Class Loader.

### Step 2

JVM verifies bytecode.

Checks:

- Security
- Format
- Correctness

### Step 3

Execution Engine starts.

### Step 4

JIT Compiler (Just-In-Time Compiler) converts frequent bytecode into native machine code.

### Step 5

CPU executes machine code.

---

# JVM Components

### 1. Class Loader

Loads classes into memory.

### 2. Method Area

Stores:

- Class metadata
- Methods
- Static variables

### 3. Heap

Stores objects.

```java
Student s = new Student();
```

### 4. Stack

Stores:

- Method calls
- Local variables

### 5. Garbage Collector

Automatically removes unused objects.

```java
obj = null;
```

Unused memory is eventually cleaned.

# Quick Interview Answers

### What is JVM?

A virtual machine that executes Java bytecode and converts it to machine code.

### What is JRE?

Runtime environment containing JVM and libraries required to run Java applications.

### What is JDK?

Development kit containing JRE and development tools such as `javac`.

### What is Bytecode?

Platform-independent intermediate code (`.class` files) generated by the Java compiler and executed by the JVM.

# Easy Memory Trick

```text
You write code      → JDK
You get .class      → Bytecode
You run .class      → JVM
Everything needed to run → JRE
```

## Final Flow

```text
.java
   ↓ (javac)
.class (Bytecode)
   ↓ (JVM)
Machine Code
   ↓
Output
```
